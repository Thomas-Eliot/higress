🔀路由优先级变更警告

⚠️ NGINX 和 Higress 的路由优先级规则不同，可能导致迁移后流量路由到不同后端。

  • NGINX 优先级：exact > regex > prefix（相同类型按创建时间排序）
  • Higress 优先级：exact > prefix > regex（相同类型按路径长度倒序）

以下 Ingress 使用了 use-regex 注解，且存在 regex 路径与 prefix 路径的优先级冲突：

序号 Host Regex 路径 (NGINX 优先) Regex Ingress Regex 后端 Prefix 路径 (Higress 优先) Prefix Ingress Prefix 后端
1 high-risk.example.com /admin(/|$)(.*) ls-test/high-risk-app admin-service:8080 /admin ls-test/high-risk-prefix admin-default-svc:80

💡 建议操作

⚠️ 此优先级差异没有完美的自动兼容方案，需要根据实际业务逐一评估：

  1. 确认实际影响：分析真实流量是否会同时命中 regex 和 prefix 路径。如果实际请求 URL 不会同时匹配两者，则优先级变化不影响路由行为
  2. 将 prefix 路径也改为 regex：给冲突的 prefix Ingress 加上 use-regex: "true"，使两者都变为 regex 类型，在 Higress 中按路径长度排序，避免优先级反转。
    ⚠️ 注意：加上 use-regex 后，原来的 Prefix 路径（如 /admin）会被当作正则表达式匹配，语义发生变化（如 /some/admin 也会被匹配到）。需要同时将 path 改写为等效的正则表达式以保持原有前缀匹配行为，例如将 /admin 改为 /admin(/|$)(.*)
  3. 缩小 prefix 路径范围：将 prefix 路径改为更精确的路径（如 /admin/dashboard 代替 /admin），减少与 regex 路径的重叠
  4. 合并 Ingress：将冲突的 regex 和 prefix 路径合并到同一个 Ingress 中，统一后端服务，消除优先级冲突
  5. 灰度验证：迁移前在测试环境用真实流量回放验证路由行为，确保关键路径不受影响
